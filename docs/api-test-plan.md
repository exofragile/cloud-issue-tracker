# API Test Plan

Run these tests against the Lab 4 API implementation. Reset or prepare the JSON data file as needed so each test has the stated starting conditions. For request-body tests, send `Content-Type: application/json` unless the test specifically covers media type handling.

Results below were recorded against the Lab 4 API running locally with `npm run dev` (`http://localhost:3000`). The same requests are saved in `evidence/lab-04-postman-collection.json` and `backend/requests.http`.

| Test ID | Scenario | Starting condition / request | Expected result | Actual Result | Pass/Fail |
|---|---|---|---|---|---|
| T01 | View all issues | `GET /api/issues` with one or more issues in the data file. | `200 OK`; response has `Content-Type: application/json` and the body is an array of complete issue objects. | 200; `Content-Type: application/json; charset=utf-8`; array with 1 complete issue (ISS-101). | Pass |
| T02 | Create a valid issue | `POST /api/issues` with a valid title, description, and priority. | `201 Created`; response is a complete issue with a generated unique `id`, trimmed client fields, `status` equal to `Open`, and an ISO 8601 `createdAt`. The new issue is persisted. | 201; complete issue with a UUID `id`, `status` Open, ISO 8601 `createdAt`; padded title/description came back trimmed; issue present in `data/issues.json`. | Pass |
| T03 | Create without title | `POST /api/issues` with title omitted and other valid client fields. | `400 Bad Request`; error code is `VALIDATION_ERROR`; no issue is added. | 400; `VALIDATION_ERROR` "Title is required." (empty title `""` gives "Title must contain between 3 and 100 characters."); issue count unchanged. | Pass |
| T04 | Create with invalid priority | `POST /api/issues` with a title and description meeting their rules and priority set to `Urgent`. | `400 Bad Request`; error code is `VALIDATION_ERROR`; no issue is added. | 400; `VALIDATION_ERROR` "Priority must be Low, Medium or High."; issue count unchanged. | Pass |
| T05 | Change existing issue status | `PATCH /api/issues/{id}/status` for an existing issue with body `{"status":"Resolved"}`. | `200 OK`; response contains the complete issue with status `Resolved`; the change is persisted. | 200; complete issue returned with status Resolved; stored status in `data/issues.json` is Resolved. | Pass |
| T06 | Change to invalid status | `PATCH /api/issues/{id}/status` for an existing issue with body `{"status":"Closed"}`. | `400 Bad Request`; error code is `VALIDATION_ERROR`; stored status remains unchanged. | 400; `VALIDATION_ERROR` "Status must be Open or Resolved."; stored status still Open. | Pass |
| T07 | Change status for unknown ID | `PATCH /api/issues/{unknown-id}/status` with a valid status. | `404 Not Found`; error code is `ISSUE_NOT_FOUND`. | 404; `ISSUE_NOT_FOUND` "Issue not found." in the standard error shape. | Pass |
| T08 | View when there are no issues | Start with an empty issue list or a missing data file; send `GET /api/issues`. | `200 OK`; response body is the empty JSON array `[]`. | 200; body `[]` for both an empty file (`[]`) and a missing file. | Pass |
| T09 | Create with server-owned fields | `POST /api/issues` with valid client fields plus client-supplied `id`, `status`, and `createdAt`. | Per this contract, the extra server-owned fields are ignored. `201 Created`; response has a server-generated ID and timestamp and status `Open`, not the supplied values. | 201; `id` is a new UUID (not `HACKED-1`), `status` Open (not Resolved), `createdAt` is the current time (not 2000-01-01). | Pass |
| T10 | Reject unsupported media type | Send a valid `POST` or `PATCH` body with a non-JSON `Content-Type`. | `415 Unsupported Media Type`; error code is `UNSUPPORTED_MEDIA_TYPE`; no data is changed. | 415; `UNSUPPORTED_MEDIA_TYPE` for `POST` and `PATCH` with `text/plain`; issue count and stored status unchanged. | Pass |
| T11 | Handle persistence failure | Make the data file unavailable or unwritable and send a valid create request. | `500 Internal Server Error`; error code is `INTERNAL_ERROR`; the API does not return a success-shaped response. | 500; `INTERNAL_ERROR` "An unexpected server error occurred."; no internal details in the response, error logged on the server; API recovered once the file was restored. | Pass |
| T12 | Create with malformed JSON (new in Lab 4) | `POST /api/issues` with `Content-Type: application/json` and a body with a trailing comma. | `400 Bad Request`; error code is `VALIDATION_ERROR`; message is "Request body is not valid JSON."; the server keeps running. | 400; `VALIDATION_ERROR` "Request body is not valid JSON."; next `GET /api/issues` returned 200. | Pass |
| T13 | Unknown route (new in Lab 4) | `PATCH /api/fake-url`. | `404 Not Found`; error code is `ROUTE_NOT_FOUND`. | 404; `ROUTE_NOT_FOUND` "Route not found." | Pass |
